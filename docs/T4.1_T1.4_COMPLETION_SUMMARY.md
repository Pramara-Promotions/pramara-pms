## T4.1: Backend Kanban Configuration ✅

### Implementation Status
**COMPLETE** - All 6 required endpoints and utility library fully implemented.

### API Endpoints (in `api/routes/projects.js`)

#### 1. GET `/api/projects/:id/board-config`
- **Purpose:** Retrieve Kanban board configuration for a project
- **Returns:** 
  - Default columns: Pre_Prod, Production, QC, Dispatch
  - Custom columns with WIP limits and colors
  - Task counts per column
- **Permission:** PROJECT_VIEW
- **Features:**
  - Auto-creates default 4-column config if none exists
  - Merges default + custom columns
  - Includes task counts from database

#### 2. POST `/api/projects/:id/board-config/columns`
- **Purpose:** Create custom Kanban column for project
- **Body:** `{ name, section, wipLimit, color }`
- **Validation:**
  - Section must be one of: Pre_Prod, Production, QC, Dispatch
  - Validates uniqueness of section per project
  - Auto-assigns sequential position
- **Permission:** PROJECT_EDIT
- **Audit:** Logs column creation with user info

#### 3. PUT `/api/projects/:id/board-config/columns/:columnId`
- **Purpose:** Update existing Kanban column
- **Body:** `{ name?, position?, wipLimit?, color? }`
- **Features:**
  - Supports partial updates
  - Position change triggers atomic reordering of all columns
  - Transaction-based to prevent race conditions
- **Permission:** PROJECT_EDIT
- **Audit:** Logs column updates with field changes

#### 4. DELETE `/api/projects/:id/board-config/columns/:columnId`
- **Purpose:** Delete custom Kanban column
- **Validation:**
  - Prevents deletion if column has any tasks (409 Conflict)
  - Validates column exists and belongs to project
- **Features:**
  - Auto-reorders remaining columns (0, 1, 2, ...)
  - Transaction-based
- **Permission:** PROJECT_EDIT
- **Audit:** Logs column deletion

#### 5. GET `/api/projects/:id/tasks`
- **Purpose:** List all tasks for a project
- **Returns:** Tasks ordered by section and position
- **Permission:** PROJECT_VIEW
- **Features:**
  - Sorted for Kanban board display
  - Full task details including assignees, attachments, etc.

#### 6. PUT `/api/tasks/:id/move`
- **Purpose:** Move task to different section and/or position
- **Body:** `{ section, position }`
- **Features:**
  - **Within-section move:** Removes task, inserts at new position, reorders
  - **Cross-section move:** Updates old section positions, adds to new section
  - All position updates in single transaction
  - Optimistic update support
- **Permission:** TASK_EDIT
- **Audit:** Logs task movement with section details

### Utility Library (`api/lib/kanban.js`)

#### `getBoardConfig(projectId)`
- Returns merged default + custom columns
- Includes task counts per column
- Handles missing Prisma models gracefully (development resilience)
- Creates default 4-column config if none exists

#### `createBoardColumn(projectId, { name, section, wipLimit, color })`
- Validates section is unique for project
- Auto-assigns next available position
- Returns created column object
- Throws appropriate errors (400, 409)

#### `updateBoardColumn(projectId, columnId, updates)`
- Supports name, position, wipLimit, color updates
- Position change logic:
  - Moving right: Shifts intermediate columns left (pos-1)
  - Moving left: Shifts intermediate columns right (pos+1)
  - Single transaction for atomicity
- Returns updated column

#### `deleteBoardColumn(projectId, columnId)`
- Validates column exists and belongs to project
- Checks for tasks (returns 409 if any exist)
- Reorders remaining columns sequentially
- Transaction-based deletion
- Returns success status

#### `moveTask(taskId, section, position)`
- **Within-section logic:**
  - Removes task from old position
  - Inserts at new position
  - Reorders all affected tasks
- **Cross-section logic:**
  - Updates old section positions (shifts up)
  - Adds to new section at position (shifts down)
- All updates in single transaction
- Returns updated task object

### Technical Features

**Security:**
- Authentication via `authGuard` middleware
- RBAC permissions: PROJECT_VIEW, PROJECT_EDIT, TASK_EDIT
- Input validation and sanitization
- SQL injection protection via Prisma

**Error Handling:**
- 400: Bad request (validation errors)
- 404: Not found (project, column, task)
- 409: Conflict (cannot delete column with tasks)
- 500: Server error (database issues)
- Descriptive error messages

**Audit Logging:**
- All mutations logged to audit trail
- Includes user info, timestamp, action details
- Queryable audit history

**Performance:**
- Transaction-based operations for atomicity
- Optimistic updates supported
- Efficient position reordering algorithms
- Indexed database queries
